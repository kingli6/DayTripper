Potential Edge Cases & Pitfalls to Address

While the spec is solid, here are a few technical blind spots to consider before shipping:
1. Authentication Token Expiry During Offline State

    The Scenario: The user goes offline, works for 3 hours, and comes back online. Meanwhile, their JWT/session token expired.

    The Risk: When the sync queue triggers, the server rejects all requests with 401 Unauthorized. If not handled carefully, the app might wipe the queue or throw generic errors.

    Recommendation: Ensure the sync engine pauses, prompts for re-authentication (or refreshes the token silently), and then flushes the queue once authenticated.

2. Network "Flapping" & False Positives

    The Scenario: Browsers rely on navigator.onLine, which only detects if the device is connected to a router—not whether the internet is actually working (e.g., captive portals, hotel Wi-Fi login pages).

    The Risk: The app thinks it is online, attempts to flush the queue, receives HTML error pages (or 504 Gateway Timeouts), and prematurely marks items as failed.

    Recommendation: Treat connection status as a "heuristic" rather than certainty. Use ping/health-check endpoints before initiating a queue flush.

3. Single-Device Overwrite (Last Write Wins)

    The Scenario: A user edits an activity on their laptop while online. Meanwhile, their phone was offline with an old version of that same day. When the phone reconnects, its queue pushes stale state over the new laptop state.

    The Risk: Unintentional data overwrites.

    Recommendation: Even without full CRDT multi-device conflict resolution, include a basic updated_at timestamp check or optimistic locking on the server (e.g., reject updates if server_updated_at > request_updated_at).

4. Account Switching / Logout Cleanup

    The Scenario: User A logs out while offline or on a shared device, and User B logs in.

    The Risk: User A's local snapshot or pending sync queue might leak to User B, or sync under User B's account.

    Recommendation: Explicitly purge all local storage queues and snapshots on LOGOUT actions.
